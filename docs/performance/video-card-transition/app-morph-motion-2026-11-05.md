# 视频卡片官方转场与应用内开合（2026-11-05）

普通视频卡片优先通过官方 SDK 调用设备的窗口转场；不满足协议或卡片来源条件时，由应用内导航承载连续形变。外部或没有卡片来源的独立视频窗口保留类型化参数入口。两条路径均不依赖 Root、修改系统允许名单或厂商私有调用，不包含 ROM 动画实现二进制。

## 运动参数与实现边界

运动行为参考及样本来源集中记录在 `app/src/main/assets/licenses/third_party_sources.NOTICE` 和 [系统调查](sharedview-rom-compatibility-2026-11-05.md)。本次使用已取得系统样本中的以下阻尼比与响应时间作为复刻依据，不代表联盟所有厂商共用这些数值。

| 通道 | 打开：阻尼比 / 响应秒数 | 返回：阻尼比 / 响应秒数 |
| --- | --- | --- |
| 中心位置 | 1.1 / 0.229 | 0.95 / 0.29 |
| 窗口尺寸 | 1.1 / 0.268 | 0.95 / 0.29 |
| 圆角 | 1.0 / 0.18 | 1.0 / 0.20 |
| 背景景深进度 | 1.0 / 0.25 | 1.0 / 0.15 |

`VideoCardMorphPhysics` 使用项目现有 Folme 参数转换和 Compose 弹簧求解器。位置、尺寸、圆角和背景分别采样；快速返回和取消恢复继承各通道当前位置与速度。手势期间直接移动，不另套自动播放曲线。

导航 entry 的生命周期仍由共享导航驱动控制，返回使用临界阻尼 1.0 / 0.29 的单调寿命弹簧，避免过冲提前卸载。几何属性保留表中的独立参数。动画读取导航 settle 的时间并适配系统动画时长比例，不额外注册每通道的帧循环。

与系统合成不同的部分仍需明确：这是应用内绘制的复刻；背景缩放/模糊强度及封面交接复用项目既有实现，没有证明与系统窗口合成完全一致。不能仅凭参数相同宣称视觉、性能或手感一比一。

## 应用内路径的来源、返回与播放器

- 点击时保存来源实例的弱引用和已有卡片像素所有权，复用已有卡片 GraphicsLayer，不重复录制一层卡片。
- 普通返回及预测返回手势开始前，重新读取原实例的矩形和圆角，并更新封面/信息面的相对测量区域与导航宿主原点。
- 原实例移除、被裁切或无法恢复时取消卡片落点，不按相同 bvid 认领另一个实例。
- 相关推荐沿应用内导航逐层返回；替换当前视频仍使用替换操作。
- SDR 画面使用现有可合成 TextureView 路径；HDR 保留播放器原有 SurfaceView 输出规则，不能保证 HDR 画面全程实时形变。
- 关闭卡片动画或系统减少动态效果时停用卡片形变。视频的逐帧采样只在开合/手势恢复期间运行，并受宿主前台与窗口可见性控制。
- 液态玻璃、MD3 和 Miuix 复用同一运动宿主，各自的页面材质和布局参数继续由原入口决定。

## 性能与官方接口复核

当前已加入 `gsai.sdk:sharedview-kit:1.0.0.5`，通过 `isViewAnimationSupported() > 0` 探测协议能力，不按品牌或系统版本硬编码判断。

官方路径要求卡片动画开启、未启用减少动态效果、来源实例完整可见且具有对应录制层；设备按 `isViewAnimationSupported()` 声明协议能力即接管打开段，返回动画类型按设备 `EXTRA_BACK_ANIM_TYPE` 声明的可写集合尽力控制（减少动效优先无动画返回，来源消失优先跟随系统，未声明的类型不写入，由设备默认策略兜底），不把仅支持部分类型的设备挡在官方路径之外。不满足条件时使用现有应用内导航。

Compose 卡片通过已有 GraphicsLayer 导出卡片 Bitmap，使用官方 Bitmap 重载生成 ActivityOptions，独立传给 VideoActivity，播放参数继续使用 VideoOpenRequest。读取像素后重新检查请求归属、来源像素身份、窗口焦点和来源位置，坐标系遵循设备 EXTRA_BOUNDS 声明。尺寸不匹配、配置返回 null 或系统以 SecurityException 拒绝启动时，保留应用内路径，不把普通 Activity 动画计作官方动画。

官方路径仅在设备声明支持时传入实时模糊偏好；首帧使用启动时的偏好，不以异步设置加载前的默认值覆盖。官方动画曲线与时长由设备引擎负责，应用内的弹簧与速度参数不替代系统动画。

官方窗口的返回配置在恢复、配置变化、动效设置变化和 finish 前刷新，弱引用打开时的同一卡片实例；来源消失或进程重建丢失锚点时改用系统返回，减少动态效果时使用无动画返回。未使用 Android 共享元素冒充官方实现。系统预测返回由窗口系统负责，应用内导航仅接管窗口内的子页面返回。

官方子窗口打开期间，保留的父详情页暂停播放所有权，返回获得焦点后恢复。关闭窗口的播放清理同时核对播放器实例，避免相同视频编号的父播放器被旧窗口停掉。配置重建保留转场令牌，最终销毁释放对应的来源与像素会话。

上述内容是源码接入状态，尚未证明任何设备实际执行了官方动画。SDK 的公开回调也不能证明系统实际采用的返回动画类型。

性能判断目前仅来自源码：

- 四个属性通道在导航帧中采样，帧内结果复用，未创建四条独立协程或帧循环；几何变换在图层阶段读取，不逐帧重测详情布局。
- 卡片实例登记只保存测量引用，像素继续复用原有录制层。位置查询发生在点击和返回准备时，不逐帧遍历列表。
- 实时模糊保留独立开关，背景模糊开启时增加图层处理成本；实时画面随卡片开合启用，SDR 的 TextureView 路径可能在详情播放期间持续使用，不能把成本限定为开合瞬间。
- 因此不能凭“四条弹簧计算量小”推断整体更省资源，也没有新版本的帧耗时、掉帧、内存或功耗测量结果。

本轮修正了一个手势时间基准问题：绝对纳秒时间不再经过 Float 缩放，改为先用 Long 求间隔再换算逻辑秒数，避免长运行时间下的精度损失。补充了长时间基准及动画时长比例用例，但尚未执行。

官方路径新增用例覆盖坐标系声明优先级、旧版元数据和返回类型支持集合。未运行 Gradle、测试或应用，不能将源码接入和用例编写等同于运行验证。应用内路径的上述性能边界仍然成立；官方窗口合成的实际成本不在本轮源码检查的结论范围内。
